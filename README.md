# JR West Super TID

JR西日本 東海道・山陽本線（琵琶湖線／JR京都線／JR神戸線）と、
湖西線・JR宝塚線（福知山線）・JR東西線の運行を再現した TID シミュレーター。

`index.html` をブラウザで開けば動きます（サーバー不要）。

## 公開先

GitHub Pages で公開しています。PCの電源が入っていなくてもアクセスできます。

**https://wata9857-ops.github.io/tid-simulator/**

`main` ブランチに push すると、1〜2分で自動的に反映されます。
（GitHub の Settings → Pages が「Deploy from a branch: main / (root)」になっています）

外部ライブラリもビルドも使っていない素の HTML / CSS / JavaScript なので、
GitHub Pages にそのまま置くだけで動きます。

### iPad で表示できるかの確認

線路図は横 31,160px の巨大なキャンバスに描いています。
iOS / iPadOS の Safari にはキャンバスの大きさに上限があり、機種によっては
確保できずに線路図が真っ白になることがあります（ヘッダーの時計は動きます）。

お使いの端末で足りるかは、下のページを iPad の Safari で開くと判定できます。

**https://wata9857-ops.github.io/tid-simulator/tools/canvas-limit-test.html**

## ファイル構成

1ファイルに全部入っていたものを、役割ごとに分けています。
`index.html` は HTML と読み込み指定だけを持ちます。

### css/

| ファイル | 中身 |
| --- | --- |
| `style.css` | 全体のレイアウト、ヘッダー、指令パッド、フッターなど |
| `header-log.css` | ヘッダーの業務連絡欄と、運転指令／業務連絡の履歴パネル |
| `depot-view.css` | 留置場の構内配線図モーダル |

### js/

**読み込み順に意味があります。** データ定義 → クラス本体 → `prototype` への追加 → 起動 の順です。
`index.html` の `<script>` の並び順を変えると動きません。

| ファイル | 中身 |
| --- | --- |
| `01-config.js` | 描画色・ブロック寸法などの基本定数、`Vehicle`（編成）クラス |
| `02-fleet-data.js` | 全編成データ（`編成番号.xlsx` から取り込んだもの） |
| `03-stations.js` | 駅一覧、番線ルール、`STATION_MAP`、線路(`TRACKS`)、臨時列車 |
| `04-depots.js` | 留置場(`DEPOTS`)と構内配線図(`DEPOT_LAYOUTS`)、在線リストの管理 |
| `05-track-manager.js` | `TrackManager` — 線路・ブロック・運転見合わせ区間 |
| `06-fleet.js` | `FleetManager` — 編成の在庫と運用の割り当て規則 |
| `07-spawner-core.js` | `Spawner` 本体と編成割当の入口 |
| `08-spawner-mainline.js` | 本線（琵琶湖線／京都線／神戸線）の列車生成 |
| `09-spawner-branch.js` | 湖西線・JR宝塚線・JR東西線の生成と尼崎合流の調整 |
| `11-train-core.js` | `Train` 本体 — 生成・初期配置・毎Tickの状態遷移 |
| `12-train-move.js` | 進行（ブロック移動）と停車判定 |
| `13-train-hold.js` | 抑止（信号待ち）判定と着発番線の選択 |
| `14-train-turnback.js` | 折り返し、小トラブル、所要時間計算 |
| `15-train-depot.js` | 消滅・入区・出区 |
| `16-train-adjust.js` | 運転整理（種別変更・間隔調整・深夜の行先変更） |
| `17-renderer.js` | `Renderer` — キャンバス描画 |
| `18-ui-core.js` | `UIManager` 本体 — 時計とヘッダーのバナー |
| `19-ui-log.js` | 業務連絡欄と運転指令ログ履歴 |
| `20-ui-cmd.js` | 指令パッド（設定変更・抑止・強制発車・転線・出区） |
| `21-ui-board.js` | 発車標（電光掲示板） |
| `22-depot-view.js` | 留置場の構内配線図 |
| `23-game.js` | `GameSystem` — メインループと異常事象、起動処理 |

ファイル名の数字は読み込み順です（`10` は欠番）。
あいだに追加したいときは、`index.html` の `<script>` の並びにも足してください。

`Train` / `Spawner` / `UIManager` は 1ファイルに収まらないので、
クラス本体を1つのファイルに置き、残りのメソッドは
`Train.prototype.メソッド名 = function (...) { ... };` の形で別ファイルに分けています。
クラスのメソッドとして書くのと動きは同じです。

## 編成（車両）の運用規則

割り当ての規則は `js/06-fleet.js` の `FleetManager.profileFor()` に集約しています。
規則を変えたいときはここだけ直せば全体に反映されます。

* 新快速は必ず **12両（8両＋4両）**。網干総合車両所の 223系／225系のみ。
* 新快速・快速に **221系／207系／321系**（221系性能の6000番台を含む）は使わない。
* 湖西線の**普通**は京都支所の **221系または223系**のみ。
  （湖西線経由の新快速・快速は網干の223系／225系）
* 京都支所の車両は本線（JR京都線／JR神戸線）の運用には入れない。
* **JR東西線内**を走る列車は **207系または321系**のみ（快速も含む）。
* JR宝塚線から**大阪方面**へ直通する列車は **223系または225系**
  （宮原支所の6000番台を優先）。
* 米原〜敦賀間と湖西線を除き、普通以上の種別は **6両以上**。
  足りないときは実際の組成にあわせて増結する（207系は4+3、223系などは4+4）。
* 留置されている編成の編成番号は、起動ごとにシャッフルして割り当てる。

### 車両所グループ

編成データの `g` で持ちます。文字列の照合ではなくこの値で判定します。

| g | 車両所 | 略号 | 主な形式 |
| --- | --- | --- | --- |
| `ABOSHI` | 網干総合車両所 | ホシ | 223系1000/2000番台、225系0/100番台 |
| `AKASHI` | 網干総合車両所明石支所 | アカ | 207系、321系 |
| `MIYAHARA` | 網干総合車両所宮原支所 | ミハ | 223系/225系6000番台 |
| `KYOTO` | 吹田総合車両所京都支所 | キト | 221系、223系2500/6000番台 |

### 在庫が足りないとき

1. 指定の留置場に条件を満たす編成がなければ、近い留置場から順に借り出す
   （`FLEET_MAX_BORROW` 箇所まで）。
2. それでも足りないときだけ、車両所ごとに `FLEET_RESERVE` で決めた本数だけ増備する。
   **上限があるので無制限には増えません**（現状の設定では合計28本まで）。

## 留置場と構内配線図

`js/04-depots.js` の `DEPOT_LAYOUTS` が構内配線図です。
同梱の配線略図をもとに、線群・留置線名・収容両数を書き起こしています。

本線上の【留置】の枠をクリックすると、構内図と在線一覧が開きます。
どの留置線にどの編成が止まっているかが分かります。
留置線は編成番号から決めるので、留置している間は同じ線に居続けます。

## 検証ツール（tools/）

ブラウザなしでシミュレーターを走らせて確認できます。ゲーム本体からは参照されません。

```
node tools/harness.js tools/check_sim.js    # 生成本数と編成運用の規則 (20時間ぶん走らせる)
node tools/harness.js tools/check_ui.js     # 遅延計算・強制発車・構内図・ログ表示
node tools/harness.js tools/check_boot.js   # 起動・描画・各UI関数を通しで実行
node tools/check_refs.js                    # HTML / JS / CSS の参照の食い違い
```

`tools/harness.js` が DOM とキャンバスをスタブに差し替えて `js/*.js` を読み込みます。
シミュレーターには乱数が入っているので、数回まわして確認してください。

分割前のコードと比べたいときは、先に基準値のソースを取り出します。

```
python tools/extract_baseline.py                        # gitから分割前のコードを取り出す
node tools/harness.js --orig tools/check_baseline.js    # 分割前の生成本数
node tools/harness.js        tools/check_baseline.js    # 分割後の生成本数
node tools/check_logic_diff.js                          # どのメソッドを変更したかの一覧
```

`tools/build_fleet_data.py` は `js/02-fleet-data.js` の生成スクリプトです。
`編成番号.xlsx` を更新したときはこれを通し直します。

```
python tools/build_fleet_data.py
```
